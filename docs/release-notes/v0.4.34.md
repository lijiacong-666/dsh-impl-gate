# 0.4.34 — 警告目录的「最小复现」表由测试守住

## 问题

`docs/WARNINGS.md` 末尾有一张「每条警告的最小复现」表（37 行，指向具体测试文件）。它是 0.4.22 用一次性脚本扫出来的，脚本当场删了，之后又加过几类警告。只要有人新增一类警告或改动测试文件名，表就会悄悄指向不存在的复现。

## 改了什么

新增 `tests/warnings-repro.test.mjs`（3 条断言）：

1. 目录表里的码集合 = 复现表里的码集合（多一行、少一行都红）
2. 每行的测试文件必须存在，且文件里真的出现该码（防止「指向一个不含这个码的文件」）
3. 复现表里不许留下已从目录删掉的码

## 验证这层守卫真的会响

故意把 `TYPE_UNUSED` 那行指向 `type-owner.test.mjs`：

```
error: 'TYPE_UNUSED: type-owner.test.mjs never mentions it'
# pass 2 / fail 1
```

`git checkout` 还原后恢复 3/3 通过。

## 当前状态

- 目录 37 类、复现表 37 行，一一对应
- 测试 333 / 通过 328 / 跳过 5

## 已知缺口

- 表里只记「哪个测试文件」，不记「第几个用例」；同一文件里多个用例时还要搜码。
- 复现表只证明「这个码在测试里被构造过」，不证明「它一定会在坏 plan 上触发」——后者靠 `pnpm smoke` 的快照，两者互补。
