# 0.4.40 — 删掉一个假装能用的开关（`slow`）

## 问题

`impl_gate_check` 有一个 `slow` 参数，配置里也有 `slow` 键，文档写着「是否运行 slow 断言（Q1 依赖审计）」。实测对同一个图：

```
slow=false | 2805ms | PASS 10 / NOT-RUN 22
slow=true  | 3273ms | PASS 10 / NOT-RUN 22
```

Q1 两次都停在 NOT-RUN。原因是这条链路有三层门：`slow` 打开第一道，第二道是 `allowCommandReplay`，第三道是首词白名单——而 Q1 的命令是 `impl-gate:clean-venv`（符号名，不可执行），永远过不了第三道。**一个参数在文档里承诺了行为，实际什么也不改变**，比没有这个参数更糟。

## 改了什么

- 删掉 `slow`：配置 schema、`Config` 类型、`CheckOptions`、`AssertionContext`、`impl_gate_check` 的参数表全部移除。
- Q1 从 `mode: auto` + `runtime: slow` 改为 `mode: notrun` + `runtime: fast`，原因码 `IMPLEMENTATION_ONLY`。
- `IMPLEMENTATION_ONLY` 加入 A2 的合法原因码表；旧勾选表里的 `SLOW_CHECK_DISABLED` 仍被接受（只读兼容），但不再产生。
- 两份 README 的 Q1 示例行、原因码表、参数表、配置表同步。

## 为什么不是「把 Q1 实现出来」

Q1 的语义是「目标项目零第三方运行时依赖」，验证方式是在干净环境里装依赖再跑测试。我们的四份实测项目都用 fastify / better-sqlite3 / vitest——**Q1 对它们本来就该 FAIL 或 NOT-RUN**，这不是本工具的职责，而是实现方 CI 的事。把它做成真的慢检查，等于让本工具去装依赖、跑目标项目的测试，边界越界且不可控。

所以这轮的选择是：**承认它不归工具管，而不是留一个假开关**。

## 测试

- `IMPLEMENTATION_ONLY` 进入 `tests/checks-consistency.test.mjs` 的原因码集合。
- 全量 346 tests / 341 pass / 5 skip / 0 fail，`tsc --noEmit` 干净。

## 升级注意

- 配置里如果显式写了 `slow`，会被 schema 拒绝（`additionalProperties: false`）——删掉那一行即可。
- `impl_gate_check` 的调用方如果传了 `slow`，参数会被忽略（未知属性不报错，但也不生效）。
- 老勾选表里的 `SLOW_CHECK_DISABLED` 不会让 A2 失败；重新 `materialize` 会把它换成 `IMPLEMENTATION_ONLY`。

## 已知缺口

Q1 现在是对「实现方自己要在干净环境里验证依赖」的提醒，工具不会替你跑。如果你的项目确实需要这条审计，写进你自己的 CI，并在 `openQuestions` 里留一句「依赖审计由 CI 负责」，评审时能看到。
