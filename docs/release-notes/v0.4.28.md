# 0.4.28 — 开发文档与包描述去脚手架化

## 改了什么

- **`package.json` 的 `description`** 之前是「把 32 条 IMPL-GATE 断言变成可调用的 DSH 工具」——只描述了 0.1 的校验器。改成描述现在的主线：把需求变成另一个 AI 能实现的详细设计文档，串起契约图谱、评审、任务卡与实现证据。
- **`docs/development.md`**：Node 要求改为 `>=22.14.0`；删掉 `src/client/` 与 `lib/client.js` 两行（客户端入口早已移除）；目录表补上 `src/host/{tools,compose,init,review,record,assertions}`、`checks/impl-gate.checks.json`、`playbooks/`、`scripts/smoke.mjs`；脚本表补 `verify:full`、`smoke`、`smoke:ci`，并把 `smoke <spec>` 改成真实行为（跑四份参考 plan 比快照）。
- **`AGENTS.md`**：去掉 `src/client/` 的构建说明；`pnpm smoke <spec>` 改为 `pnpm smoke`；命令段补 `verify:full`。
- **`CONTRIBUTING.md`**：提交前检查改为 `pnpm verify`（有夹具与 Python 时用 `verify:full`）。

## 为什么

`description` 是 npm 搜索结果里唯一的一段话，它写着「校验器」会让人以为这是个测试工具；而实际主线是「需求 → 设计文档」。三份开发文档同理：`src/client/` 不存在、`smoke <spec>` 不存在，照着做会直接失败。

## 已知缺口

- `docs/development.md` 仍保留 `.dsh-dev` 隔离开发流程的整段说明；那是模板提供的通用做法，本机实际用的是「profile junction + 插件页开关」。两种都写成可用，没有删掉前者。
- npm 页面上的 `description` 要等下一次发布才会更新。
