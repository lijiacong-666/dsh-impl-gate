# 0.4.17 — 声明的响应类型要和处理函数对得上

## 改了什么

- 新增警告 `HTTP_RES_MISMATCH`（第 34 类）：路由的 `res` 与处理函数返回类型不一致时提醒，例如：

  ```
  GET /work-items declares WorkItem, handler handleList returns WorkItem[]
  ```

- 只比「`T` / `T[]` 这种简单类型」；`Promise<…>` 会先剥掉；`register*`（注册器）不参与比对——它一次挂多条路由、返回 `void`，其返回类型不代表任何单条路由的响应。

## 为什么

这是 0.4.14 沉默清单实验里 mini 的第三处 blocking：`§4.4` 写 `GET /work-items` 返回 `WorkItem`，而 `listWorkItems` 返回 `Promise<WorkItem[]>`、§8 又写「列表不包裹」。三处对不上，调用方按契约写就编译不过。

## 实测

| plan | `HTTP_RES_MISMATCH` |
|---|---|
| mini | 1（正是评审抓的那条） |
| pillbox | 0 |
| run-log | 0（一开始 5 条误报全部来自 `registerUiRoutes`，加注册器豁免后归零） |
| fitness | 0 |

## 升级注意

- 旧 plan 可能新出一条：把 `res` 改成 `T[]`，或把处理函数签名改成返回 `T`。
- 如果你的处理函数返回联合类型（`T | null`），本检查跳过——那属于「不存在时返回什么」，靠评审与 `errors[]` 覆盖。

## 已知缺口

- 比的是字面类型名；`Page<T>` 这类泛型包装不解析（会跳过）。
- 不检查请求体 `req` 与处理函数参数类型是否一致（同源问题，下版再补）。
