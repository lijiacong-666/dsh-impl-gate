# 0.4.11 — 环境变量必须在 `envKeys` 里登记

## 改了什么

- 新增警告 `ENV_KEY_UNDECLARED`（第 31 类）：`runtime.start` / `runtime.health` / `runtime.migrate` / `runtime.rollback` 里出现 `NAME=…` 形式的环境变量赋值，而 `globals.envKeys` 没有这个键时提醒。
- 只认 `大写+下划线` 且后面紧跟 `=` 的写法（`APP_PORT=3000 node server.js`），不猜 `$NAME` 这类间接引用。

## 为什么

药箱 e2e 里部署那一段写着 `PILLBOX_PORT=<port> node web/server.js`，但 `envKeys` 一开始没有 `PILLBOX_PORT`——读文档的人不知道这个值的来源、缺省和由谁设置。这类「命令里用了、清单里没写」的键，机器一查就能发现。

## 实测

pillbox / fitness / run-log / mini 四份 plan 均为 0（pillbox 早已把 `PILLBOX_PORT` 补进 `envKeys`），说明只对真正的漏登记报。

## 升级注意

- 旧 plan 不需要改；如果 `runtime` 命令里内联了 `NODE_ENV=production` 这类键，会新出现一条警告——把它加进 `envKeys` 即可。

## 已知缺口

- 只查「赋值」这一种用法；`--port $PORT`、`process.env.X` 这些间接引用查不到。
- 不校验 `envKeys` 里列了却从没用过的键（反向漏报）。
