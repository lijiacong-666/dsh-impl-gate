# 0.4.16 — 有路由却没有宿主

## 改了什么

- 新增警告 `HTTP_NO_HOST`（第 33 类）：plan 声明了 `http[]` 路由，但没有任何模块暴露服务器入口（`listen(` / `startServer(` / `buildServer(` / `createApp(`）时提醒，条目是那几条无处安放的路由。

## 为什么

这是 0.4.14 沉默清单实验里被评审抓到的 blocking：`mini` 的 SPEC 声明了 `POST/GET /work-items` 与 201/200，但交付清单里只有 `core/work.mjs`、迁移 SQL 与测试，没有任何文件承载 HTTP 层——端口、启动命令、健康检查全缺。评审者据此判「不可开工」。

旧警告都盖不到它：`HTTP_ROUTE_UNCOVERED` 说「没人断言这条路由」，`AC_HTTP_OUTSIDE_SHELL` 说「模块自己没有路由却断言 HTTP」，都不等于「整张接口面没有宿主」。

## 实测

| plan | `HTTP_NO_HOST` |
|---|---|
| mini | 2（`POST /work-items`、`GET /work-items`）——正是评审判 blocking 的那两条 |
| pillbox | 0（M8 有 `listen`/`buildServer`） |
| run-log | 0（M6 有 `buildServer`） |
| fitness | 0（M8 有 `listen`） |

## 升级注意

- 纯函数库或纯 CLI 的 plan 不会误报（没有 `http[]` 就不检查）。
- 如果你的宿主是用脚本（而非 TS 函数）启动的，请让壳模块暴露一个入口函数，或在 `runtime.start` 里写清楚——否则实现者仍然不知道谁 listen。

## 已知缺口

- 只认四种常见入口名；`serve(`、`http.createServer(` 这类不会被认作宿主（可以加进正则，但要防误报）。
