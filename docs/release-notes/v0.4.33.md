# 0.4.33 — 案例文档的数字不再靠手工维护

## 问题

三份 `docs/CASE-STUDY-*.md` 里写了大量具体数字：SPEC 行数、路由数、AC 数、源文件行数。这些文档在 0.4.0–0.4.32 之间改了十几轮，数字开始漂移——例如药箱的 SPEC 从 1114 行涨到 1126 行、AC 从 48 条涨到 49 条，文档里还写着旧值。

## 改了什么

- **新增 `pnpm stats`**（`scripts/case-study-stats.mjs`）：打印 mini / fitness / pillbox / run-log 四份案例的模块数、路由数、AC 数、白名单文件数、SPEC 行数与字节数；产物不在时明确 `skipped` 而不是报错。
- **修正文档里的漂移**：mini 的 `SPEC.md` 100→150 行、评审实验 149→150 行；pillbox 的 `SPEC.md` 1114→1126 行 / 72→75 KB、`48 条 AC`→`49 条 AC`、`PASS 48`→`PASS 49`。
- **加「数字口径」尾注**：三份案例都写明数字取 0.4.33 快照、产物在仓库外、以 `compose-plan.json` 与实际 `SPEC.md` 为准，避免下次再当成永久事实引用。
- `docs/development.md` 的脚本表加 `pnpm stats`。

## 实测

```
$ node scripts/case-study-stats.mjs
mini     | modules 1 | routes 2  | ac 3  | whitelisted files 3  | spec 150 lines / 4.1 KB
fitness  | modules 8 | routes 24 | ac 41 | whitelisted files 42 | spec 1273 lines / 97.9 KB
pillbox  | modules 9 | routes 22 | ac 49 | whitelisted files 38 | spec 1126 lines / 75.3 KB
run-log  | modules 7 | routes 18 | ac 21 | whitelisted files 34 | spec 789 lines / 46.7 KB
```

```
$ node --test "tests/*.test.mjs"
# tests 330 / pass 325 / fail 0
```

## 已知缺口

- `pnpm stats` 只是打印，不做断言：文档数字写错时它不会让 CI 红。要让 CI 也守住，得把四份案例产物（约 2 MB）纳入仓库或做成下载步骤，目前没做。
- 案例里的「实现者自定决定数」（14/16/10/9/16 条）没有机器来源，仍靠人读实现者报告统计。
