# 0.4.39 — 评审轮次的缺口不再让下一轮编号撞车

## 问题

`review.json` 是追加写的，但人会手工删条目。旧逻辑把「下一轮」算成 `rounds.length + 1`：

```
盘上已有 round 1、round 3（中间的 2 被删了）
rounds.length = 2 → 下一轮 = 3 → REVIEW_ROUND_EXISTS
```

于是调用方被要求「pass a new round number」，但真正的问题是编号算法假设了连续性。

## 改了什么

下一轮默认取 **盘上最大轮次 + 1**（`reduce(max)`），不再是「条数 + 1」。显式传 `round` 仍然优先，允许补录历史轮次（此时 `blockingDelta` 与「该轮之前最近的一轮」比，语义不变）。

## 测试

`tests/review-rounds.test.mjs` 三例：

1. 第一轮没有 `blockingDelta`（不会凭空说「不变 0」）
2. 盘上 1、3 → 默认下一轮是 4，且 `blockingDelta === 0`
3. 删掉 `review.json` → 重新从 1 开始，且 `blockingDelta` 再次为 `undefined`

第 2 例在旧代码上会直接报 `REVIEW_ROUND_EXISTS`。

## 实测

```
# tests 346 / pass 341 / fail 0 / skipped 5
```

## 已知缺口

- 删文件重来会让「历史」消失——`review.json` 没有备份，也不进 git（在 `.impl-gate/` 里），丢了就是丢了。
- `blockingDelta` 只在「之前有更小的轮次」时出现；补录一个中间轮次时，它与前一轮的差值有意义，但 `check` 的 `reviewSummary` 只回显最新轮，看不出补录。要看清得读 `review.json` 本身。
