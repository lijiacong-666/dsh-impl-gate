# v0.3.5 — 评审记录能证明「评的是哪一版」

实写实验的最后一条元结论：五轮评审对 12 条缺口命中 0，而且 `review.json` 里没有版本指纹，无法证明「每轮修的是同一份文档、评的是新版」。本版补上证据链。

## 改动

- 每轮评审记录 `planSha256`（`compose-plan.json` 的 sha256）与 `specSha256`（`SPEC.md` 存在时）。
- 返回值新增 `planSha256` / `specSha256` / `blockingDelta`；渲染出 `plan sha256: … / spec sha256: …` 与 `blocking vs 上一轮: 减少 N`。
- `verdicts[].evidence` 可选，必须是 `SPEC.md:<行号>`，否则 `REVIEW_INVALID`。

## 升级注意

- 旧 `review.json` 不含 sha 字段，仍可继续追加新轮次；老轮次没有指纹，不做补写。

## 已知缺口

- sha 只证明「文档没变/变了」，不证明「变化解决了问题」。
- `data[].aggregates` 仍未建模。
- 留白类缺口（排序、越界处理、依赖版本）仍只能靠评审者读原文，工具判断不了。
