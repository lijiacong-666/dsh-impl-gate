# 0.4.13 — 同一个字段名，单位必须一致

## 改了什么

- 新增警告 `UNIT_INCONSISTENT`（第 32 类）：同一个数值字段名出现在多个类型里、单位却不一致（包括一边写了、一边没写）时提醒，例如：

  ```
  lowStockThreshold (Medicine:片, StockLevel:（无）, MedicineInput:片, StockSettingsPatch:片)
  ```

## 为什么

药箱第 13 轮评审里被人工抓到的那条，就是这个问题：`Medicine.lowStockThreshold` 标了「片」，`StockLevel.lowStockThreshold` 没标。两个类型都合法、单看都没毛病，合起来就是「存储以片计、库存视图以未知计」。`UNIT_MISSING` 抓不到它，因为 `lowStockThreshold` 不在量词白名单里——它只对「像量的词」生效，对「同一个名字在别处有单位」无能为力。

## 实测

- 四份真实 plan（pillbox / fitness / run-log / mini）均为 0。
- 把药箱的 `StockLevel.lowStockThreshold` 的单位删掉后立刻报出上面那行；补回「片」即消失——与第 13 轮人工评审的结论逐字对应。

## 升级注意

- 旧 plan 可能新出一条警告：同一个数字字段在 A 类型有单位、B 类型没有。补单位或改名即可。
- 真属不同粒度的字段请改名（`durationMin` / `durationSec`），不要靠「类型不同所以可以不同」硬扛——机检认名字。

## 已知缺口

- 只按字段名精确匹配；`amount` 与 `totalAmount` 这类同义不同名的不认。
- 不校验量纲换算（同一「分钟」，一处按 60 秒算、一处按 100 秒算查不出来）。
