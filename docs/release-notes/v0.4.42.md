# 0.4.42 — `report` 的根参数报错说清该给哪一个

## 问题

第一次用报告时很容易这样：

```
impl_gate_check  graphRoot=…/pillbox/pillbox  implRoot=…/pillbox
impl_gate_report root=…/pillbox               runId=…
→ E_NO_PRIOR_RUN — run … was produced for a different root
```

`check` 收两个根，`report` 只收一个；`report` 的 `root` 必须与 `check` 的 `graphRoot` 一致，但报错只说「不同根」，没说是哪一个给错了。

## 改了什么

- 跨根报错的 `detail` 追加 `pass the same graphRoot you gave impl_gate_check (not implRoot)`，同时仍打印两个实际路径，方便对照。
- 没有改参数名——`root` 同时被 `report`/`verify_contract` 使用，改名会牵动两处 schema 与文档，收益不值。

## 测试

全量 350 tests / 345 pass / 5 skip / 0 fail；`tsc --noEmit` 干净；包 88 文件 193,705 B。

## 已知缺口

`report` 与 `verify_contract` 的 `root` 语义靠文档与报错提示，没有在 schema 描述里写死「这是 graphRoot」；下一轮若要彻底消除歧义，可以把两者的参数描述改成 `graphRoot（与 impl_gate_check 相同）` 并同步两份 README。
