# v0.3.6

## 改动

- 新增第七个工具 `impl_gate_record`：把 `compose-plan.json` 里每条验收的 `test` 命令真跑一遍，记录 PASS/FAIL、退出码、耗时与日志尾部，写到 `<outDir>/.impl-gate/ac-evidence.json`；`tasks/` 存在时同时刷新 `tasks/EVIDENCE.md`。
- 命令执行有白名单（首词 `pnpm`/`npm`/`node`/`python`/`git`/…），其余记 `SKIPPED` + `RUNNER_NOT_ALLOWED`，不会执行任意字符串；`dryRun: true` 只登记不执行。
- 这是「实现证据」：`impl_gate_review` 判文档，`impl_gate_record` 判代码对文档的执行结果。它不改 gate 的 32 条判定，也不自动勾选 checklist。
- `collectWarnings` 新增 `AC_SHELL_LATER`：某模块的 HTTP 级验收落在比 shell 模块更早的波次时给出警告（`M2: AC-M2-1 runs in wave 2, shell M6 is wave 4`），避免“这一波根本起不了服务”的验收被写成可执行断言。
- 另外三类「留白」警告：`STATUS_DEFAULTED`（写路由没写成功状态码）、`LIST_ORDER_UNDEFINED`（列表响应没有排序口径）、`PATCH_NULLABLE_AMBIGUOUS`（PATCH 请求全可空，分不清“未提供”与“置空”）。这三类正是外部诊断里“文档没写、只能自己拍板”的高频项。
- `impl_gate_check` 增加 `implementation` 字段：读到 `.impl-gate/ac-evidence.json` 时连同 PASS/FAIL/SKIPPED 一起打印，证据若是旧 plan 上跑的会标 stale。
- 任务卡第 6 节「验收断言」多一列「验收命令」，直接写 plan 里的 `acceptance[].test`，编号也用 plan 的 AC id（不再另编 `AC-M1-1`）。

## 升级注意

- 工具数从 6 变 7；宿主若对工具列表做了硬编码，需要刷新。
- `.impl-gate/ac-evidence.json` 是新增产物，不进 `ownership.json` 的生成登记（由 record 自己维护），重复 materialize 不会删除它。

## 已知缺口

- `record` 只跑命令、不看输出语义：退出码 0 就算 PASS，哪怕命令是 `true`。要防这个，只能在评审里看 `acceptance.test` 是否真的调用了被测代码。
- 无并行：命令串行执行，大型测试集会把工具调用拖到分钟级；`timeoutMs` 默认 120s，超时记 FAIL + `TIMEOUT`。
- 仍需人工：命令失败后的归因（契约错还是实现错）工具不判，交给 `check` 的 FAIL 处理流程。
