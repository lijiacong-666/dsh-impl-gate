# 0.4.32 — 示例 plan 现代化，并保证它不再腐坏

## 问题

`playbooks/examples/login.md` 是模型写 plan 时唯一能抄的完整样例。它还是 0.2 时代的形状：没有 `flows`、`ui`、`runtime`，路由不写 `auth`/`status`，类型没有 `owner`，数值字段没有 `unit`，也没有任何模块拥有 `package.json`。

把它原样贴进 `impl_gate_compose` 会得到 **6 类警告**（`COVERAGE_GAP`、`ERROR_OWNER_MISSING`、`BOUNDARY_UNUSED`、`HTTP_ROUTE_UNCOVERED`、`HTTP_NO_HOST`、`TOOLING_UNOWNED`）——示例本身就是反面教材。

## 改了什么

**示例 plan 补齐到 0 警告**：

- 每条路由写明 `auth` 与成功 `status`，新增 `GET /auth/me`（`session`，200）演示受保护路由
- `types` 补 `owner`（`User`→M2、`TokenPair`→M3），并给 `TokenPair.expiresInSeconds` 加 `unit: "秒"`
- 新增 `flows` F1（登录 → 建号 → 取连接池，含失败码）
- 新增 `ui` P1（登录页，`calls: ["POST /auth/login"]`）
- 新增 `runtime`（端口 8080、`pnpm start`、`/healthz`、`pnpm migrate`）
- M1 的文件里加 `package.json`/`tsconfig.json`（工具链归属），M3 加 `startServer`（HTTP 宿主）、`auth-api/server.ts`、`auth-api/me.ts`
- 每条 AC 补 `covers`（G1/G2/G3），新增 `auth-me` 一条 AC 覆盖新路由
- 错误码补 `by: "M3"`

**实测复现**：9 个文件、3 波、0 条警告、`SPEC.md` 200 行 / 6.2 KB。

**示例产物段重写**：原来贴的是 `_probe/g2-live`（旧骨架、`"modules": 3`），现在贴的是这份 plan 的真实产物树与关键数字。

**新增 `tests/examples.test.mjs`**（2 条断言）：示例 plan 必须通过当前 `validatePlan`，且必须演示 `flows`/`ui`/`runtime`/`auth`/`status`/`owner`/`unit`。示例再腐坏时测试会红，而不是等下一个人抄错。

## 已知缺口

- 示例仍只覆盖「单一路由 + 一张表」的规模；真实项目里的分页、批量、软删除没有在示例里出现（它们在案例文档里）。
- `tests/examples.test.mjs` 只验证「字段存在」，验证不了「这些字段的内容写得对不对」。
