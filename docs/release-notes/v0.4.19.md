# 0.4.19 — 一次 `check` 就能回答「能不能交付」

## 改了什么

- `impl_gate_check` 的输出新增 `readiness: { ok, reasons[] }`，与 `impl_gate_report` 用的是同一个判定函数（没评审 / 没证据 / 评审与证据矛盾 / 覆盖不足）。
- 渲染：

  ```
  readiness: ready to hand over
  ```

  或

  ```
  readiness: not ready — 2 reason(s)
    - no implementation evidence has been recorded
    - implementation coverage 2/3 AC recorded — missing AC-M1-1
  ```

## 为什么

`check` 是日常跑得最多的命令，`report` 才给「可分发」结论。结果是大家看完 `PASS 10 / NOT-RUN 22` 还要再跑一次 `report` 才知道能不能交。把同一判定搬到 `check`，一次调用把四件事说完：契约检查、实现证据、评审轮次、能不能交付。

## 实测（药箱）

```
PASS 10 / FAIL 0 / NOT-RUN 22 (32)
  (19 of them are implementation-side gate assertions — this tool does not parse source code, so they stay NOT-RUN by design)
implementation evidence: PASS 49 / FAIL 0 / SKIPPED 0 (49 AC)
implementation coverage: 49/49 AC recorded
review: round 14 by judge-units2 — ready 9 / clarify 0 / blocked 0 (blocking 0)
consistency: review and implementation evidence agree
readiness: ready to hand over
```

## 升级注意

- 输出多一行；如果下游脚本在解析 `check` 的纯文本，请按行匹配，不要按行数。
- `readiness` 反应的是「设计 + 证据 + 评审」的合成状态，与 A1–A5 的 `ok` 不是一回事（后者只判契约格式）。
