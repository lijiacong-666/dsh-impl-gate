# 0.4.10 — 数值字段的单位

## 改了什么

- `types[].fields[]` 新增可选 `unit`：字段有物理量时必须写单位（`分钟`、`片`、`分`），渲染进 §4.2 的「单位」列。
- 新增警告 `UNIT_MISSING`（第 30 类）：数值字段名像量（`duration`/`weight`/`quantity`/`amount`…），既没有 `unit`，名字里也没带单位时提醒。
- 名字里已带单位的字段（`distanceM`、`weightKg`、`paceSecPerKm`）不报——这是与「四份真实 plan 零误报」对齐后加的口径。

## 为什么

药箱 e2e 里多个实现者都卡在同一处：`Medicine.currentQuantity` 是「片」还是「盒」？契约没写，实现者只能自己拍一个，下游（低库存阈值、首页提醒）跟着一起偏。

## 实测

| plan | `UNIT_MISSING` |
|---|---|
| pillbox | 4（`Medicine.currentQuantity` 等，确属未定义） |
| fitness | 0（`weightKg`/`volumeKg` 已在名字里） |
| run-log | 0（`distanceM`/`durationS`/`paceSecPerKm` 同） |
| mini | 0 |

## 升级注意

- 旧 plan 不需要改；只是可能多出一条 `UNIT_MISSING`。
- 加了 `unit` 的字段会让 §4.2 表多一列「单位」——依赖旧表头的测试需要放宽。

## 已知缺口

- 单位只做「有没有写」，不校验量纲是否一致（同一概念在两个模块里一个写「分钟」一个写「秒」查不出来）。
- 中文散文里用「库存数量以片计」这类说法仍然匹配不到字段，这类只能靠评审。
