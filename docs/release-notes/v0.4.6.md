# 0.4.6

部分实现不再看起来像全部实现。

## 变更

- `check` 的 `implementation` 增加 `coverage: { declared, recorded, missing[] }`：拿 `compose-plan.json` 里每条 AC 的 id 与 `.impl-gate/ac-evidence.json` 对账（`id` 与 `ref` 任一命中都算），列出没录过的 AC。
- 渲染多一行：

  ```text
  implementation coverage: 49/49 AC recorded
  implementation coverage: 2/3 AC recorded — missing AC-M1-1
  ```

- `report` 的 `readiness` 把覆盖不足算作不能交付：

  ```text
  readiness: not ready — 1 reason(s)
  - implementation coverage 2/3 — missing AC-M1-1
  ```

## 为什么需要它

`impl_gate_record` 支持「只跑一个模块、保留其它模块的证据」。这个便利有个副作用：只录了 2 条 AC 时，`implementation evidence: PASS 3 (2 AC)` 看起来也是「通过」，读者不会追问「你总共几条 AC」。现在两者并排显示，缺的那条会被点名。

## 边界

- 对账只认 id / `AC-<module>-<n>` 两种形态；手写证据时如果自己发明编号，会被当成「未覆盖」——这是有意的，宁可多报。
- 计划里没有 `acceptance` 的模块不计入分母。

## 升级注意

严格校验 `check` / `report` 返回键集的脚本需要放行 `coverage`。
