# 0.3.17

## 改了什么

- `playbooks/review.md`：五类必查扩成**六类**，新增「散文与类型表是否对得上」——散文里点名的
  `Type.field` 必须在字段表里、页面渲染签名要说清数据从哪来、同一概念只允许一个名字。
- 回灌规则新增一条：一个字段的修复要同时落到 `types[].fields`、`constraints`、`http[].query/req` 三处；
  只改一两处，下一轮评审照样打回（药箱盲测第 4→5 轮就是证据）。
- 新增 `docs/CASE-STUDY-pillbox.md`：六轮评审、blocking 2→0、9/9 模块可开工的全过程与数字。

## 效果

评审手册现在把「工具查得到的」与「只能靠看出来的」分开列；`CONSTRAINT_FIELD_UNKNOWN`（0.3.16）
覆盖其中的显式写法，剩下的反向检查与命名一致性仍由人/评审承担。

## 已知缺口

- 同义命名（`date` / `slotDate`）目前没有机检，只在手册里要求。
- 渲染函数「数据从哪来」只能靠评审读签名判断，工具不建模渲染入参。
