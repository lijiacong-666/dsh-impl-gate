# v0.4.45 — 引擎随插件自带

市场复审（[PR #13829](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/pull/13829)）指出：按条目安装后第一次检查就报 `PYTHON_ENV_MISSING`，因为校验引擎 specgraph 是个没有公开获取方式的 Python 包。这一版把引擎打进 npm 包。

## 改了什么

- **自带引擎**：`engine/specgraph/`（固定版本，随插件升级）被加入 `files`，`npm pack` 会带上。
- **解析顺序**：显式 `specgraphCwd` > 从 `outDir` 上溯 > `SPECGRAPH_HOME` > 自带引擎。前三者保持原语义，自带引擎只在前三者都找不到时启用——本地已有检出不会被悄悄换掉。
- **错误信息**：`PYTHON_ENV_MISSING` 的文案改成「装 Python ≥ 3.11，或显式指向 specgraph 检出」，并列出探测轨迹（含 `bundled engine: <路径>`）。
- **文档**：`docs/install-specgraph.md` 重写为「什么都不用装」；中英文 README 各加一条前置说明。
- **打包守卫**：`scripts/check-package.mjs` 把 `engine/specgraph/__init__.py` 与 `engine/specgraph/checks.py` 列为必含。
- **测试**：新增 `tests/engine.test.mjs`（4 例：引擎在包内、解析回落、显式覆盖、`python -c "import specgraph"` 真跑一次，无 Python 时 skip）。

## 验证

```
# 全新目录、不给 specgraphCwd：
buildCompose({outDir: <temp>, mode:'materialize'}, {specgraphCwd:''})
→ {"ok":true,"files":9,"waves":3,"warnings":[]}
```

即安装插件 + 有 Python 即可物化，不再需要外部仓库。

## 已知限制

- 仍然需要 Python ≥ 3.11（引擎只用标准库 `tomllib`）。
- 自带引擎是快照：上游 specgraph 更新后需要随插件升级，想跟进上游可用 `specgraphCwd` 覆盖。
- 只把 `specgraph/` 包与 `web/` 资源打包，不含上游的 `tests/`、`examples/`、`docs/`。
