# 0.4.4

`impl_gate_check` 现在会对比「评审结论」与「实现证据」，把两者的矛盾直接说出来。

## 变更

- `CheckPayload` 新增 `consistency: { ok, reasons[] }`：
  - 评审有 blocked / blocking，却已经录了实现证据 → 报；
  - 评审或证据是针对旧 plan / 旧 SPEC 录的 → 报；
  - 实现证据里有 FAIL 行 → 报；
  - 评审全 ready 但一行证据都没有 → 报「还没开始记录」。
- 渲染新增一行：`consistency: review and implementation evidence agree`，不一致时逐条列出（`consistency: 2 note(s)`）。
- 只有两边都没有记录时不输出该字段，避免空噪声。
- `tests/consistency.test.mjs` 6 例（一致 / blocking / 双 stale / 证据 FAIL / 只有评审 / 都没有）。

## 升级注意

`check` 的输出多了一个可选对象。如果你的脚本对 `impl_gate_check` 的返回值做了严格键集校验，需要放行 `consistency`。
