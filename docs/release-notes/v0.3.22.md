# 0.3.22

## 改动

- 新增警告 `QUERY_PARAM_UNMAPPED`：路由声明了查询参数，而它 handler 的参数类型（如
  `handleListMedicines(query: MedicineQuery)`）里没有同名字段。这时参数没有通道传下去，
  实现者只能自己发明（塞 header、改签名、或干脆忽略）。
- 这条检查直接来自一次真实事故：药箱 `GET /api/medicines` 加了 `page`/`pageSize`，约束、`http[].query`、
  AC 三处都改了，`types[].fields` 漏了，连续两轮评审（第 5、7 轮）靠人眼抓出来。
  现在把同一份 plan 去掉那两个字段重跑，工具会自己报：
  `GET /api/medicines declares page, pageSize but MedicineQuery has no such field`。
- 真实 plan 复核：pillbox / run-log / fitness 均无误报（handler 的参数类型要么未声明，要么字段齐全）。

## 升级注意

- 纯新增警告；只在该路由的 handler 签名能解析出已声明对象类型时才判定，避免把裸参数误报。

## 已知缺口

- 只查「名字对不上」，不查「字段类型对不上」（`page` 在类型里是 `string`、在查询参数里是 `number`）。
- 流程散文（`flows[].steps[].note`）里的调用名仍无法自动核对——第 8 轮的那条 blocking 就是它。
