# 0.4.1

A3 不再只检查 `file:` 证据有没有 `:line`：文件存在时还要检查行号不超过该文件的行数。

## 变更

- `src/host/assertions/input.ts`：新增 `resolveEvidenceFile` / `countLines`，按 `implRoot` → `implRoot 上级` → `graphRoot` → `graphRoot 上级` 依次解析相对路径；文件存在且行号越界时报 `A1: SPEC.md:9 is past the end of the file (3 lines)`。文件不存在时跳过——设计期引用尚未写出的实现文件（`src/foo.ts:10`）仍然合法。
- `tests/checklist-a3.test.mjs`：新增两例（越界 FAIL、文件内 PASS、缺失文件跳过）。
- README「验收表」段补一句该行为。

- `impl_gate_check` 回显评审时同时比对 `SPEC.md` 的哈希：plan 未变、SPEC 被重新渲染（比如升级了插件）时，会提示 "recorded against an older SPEC.md"，不再把旧评审当成现行结论。`review` 载荷新增 `staleField`（`plan` / `spec` / 空）。
## 升级注意

自建勾选表如果写了「文件第 N 行」而 N 超出当前行数，会从 PASS 变 FAIL。多数情况是把行号写死后又删了一行文案，改行号即可。

## 已知缺口

- 仍不校验该行内容是否真是所声称的证据（只看行号范围）。
- 不存在文件的证据只能靠评审人工核对。
