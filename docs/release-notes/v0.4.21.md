# 0.4.21 — 声明了却没人用的类型

## 改了什么

- 新增警告 `TYPE_UNUSED`（第 37 类）：`types[]` 里声明了某个类型，但所有模块签名、路由的 `req`/`res`、查询参数类型、以及其它类型的字段都没提到它。

  ```
  TYPE_UNUSED (1): GhostShape
  ```

## 为什么

改设计时最容易留下的垃圾就是「旧类型」：字段换了、路由换了，`types[]` 里那一段没人删。读文档的人会以为它有用，照着 `GhostShape` 编一个实现，最后没人要。

## 精度（这版特意放宽了语料）

第一版只扫模块的 exposes/constraints/AC，结果药箱报 11 条、fitness 5 条、run-log 3 条——全是误报：`Reminder` 是 `ReminderList` 的元素、`PlanSlot` 只出现在 `MedicationPlan.slots` 的字段类型里、`MedicineSort` 只出现在查询参数字符串。加了「其它类型的字段类型」「路由 `handler` 名」「查询参数类型」三类语料后，四份真实 plan 全部为 0。

## 实测

| plan | `TYPE_UNUSED` |
|---|---|
| pillbox / fitness / run-log / mini | 0 |

外部类型（`kind: "external"`，例如 `FastifyApp`）不参与——它们本来就不要求本仓库定义。

## 升级注意

- 旧 plan 若真有孤儿类型，会新出一条；删掉即可。
- 如果类型只被散文「提及」（例如「返回一个 `GhostShape`」而不在签名里），仍会被判孤儿——这是故意的：散文里的类型名下游 `import` 不到。
