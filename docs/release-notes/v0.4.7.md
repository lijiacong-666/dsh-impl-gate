# 0.4.7

`verify_contract` 顺带回答「交付这套东西够不够」，不用再单独跑一次 `check`。

## 变更

- `VerifyPayload` 新增 `delivery: { ok, checks: [{ id, status }] }`，覆盖 B1（映射表）、B2（勾选表 id 集合）、B5（映射表覆盖模块）、B7（FAIL 行带复现）四项——它们本来就在同一次 `check` 的结果里。
- 渲染新增两行：

  ```text
  delivery contract: B1 PASS / B2 PASS / B5 PASS / B7 PASS
  delivery: ok
  ```

  缺项时：

  ```text
  delivery contract: B1 PASS / B2 PASS / B5 NOT-RUN / B7 FAIL
  delivery: not ok — the list above names what is missing
  ```

- `ok` 的语义不变：仍然是 A1–A5 是否全过。`delivery` 是附加信息，不改变这个工具的既有契约。
- 测试补 2 例（A 组全过但 B 组缺项、B 组逐项状态）。

## 为什么合并

`verify_contract` 的设计前提是「只读同一次 run 的缓存」。既然 B 组结论也在缓存里，让它顺带给出是零成本的；分两次调用只会让读者以为要分别判断。

## 升级注意

返回多了一个对象；严格校验键集的脚本需要放行 `delivery`。
