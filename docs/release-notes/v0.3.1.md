# v0.3.1

## 改动

- **plan 模式可以在真实项目里用了**：不再因为 `outDir` 非空而报 `E_OUT_DIR_NOT_EMPTY`；只拦「已有 `compose-plan.json` 且没传 `overwrite:true`」（`E_PLAN_EXISTS`）。
- **重跑 materialize 不再抹掉验收证据**：`PASS`/`FAIL` 行连同 evidence 原样保留，旧 `checklist.md` 先备份为 `.impl-gate/checklist.md.bak-<时间戳>`；结果新增 `checklistPreserved` 与 `checklistBackupPath`。
- **warnings**：materialize 返回 `COVERAGE_GAP` / `ERROR_OWNER_MISSING` / `AUTH_UNSPECIFIED`，把「能生成但该被看见」的缺口显式列出。
- **陈旧产物检测**：`ownership.json` 记 `plan_sha256`、`generated_at`、`managedBy` 真实版本；改了 plan 未重跑时，`impl_gate_check` 输出 `stale design: …`。
- **A3 修复**：`command: … exit:0` 里的 `exit:0` 不再被当作命令参数重放（此前会以 `exit 2 / unrecognized arguments` 误判 FAIL）。
- **export 口径统一**：`export/export.md` 顶部说明技术栈以 `plan.stack`、文件白名单以 `tasks/` 为准；specgraph 原文的「语言与结构由实现者自选」只适用于任务卡未约束的内部细节。

## 升级注意

- 老项目的 `ownership.json` 没有 `plan_sha256`，首次 `impl_gate_check` 不会报陈旧，重跑一次 materialize 后开始生效。
- 保留的 `PASS`/`FAIL` 行不会因 plan 改动自动失效：改 plan 后需人工复核这些 evidence 是否仍成立（`impl_gate_check` 只校验三态与 `## 未覆盖` 对称）。

## 已知缺口

- `flows[]`（时序/流程）、运行/部署、安全与性能、UI、请求/响应示例、前端交互尚未建模。
- `tasks/` 在 plan 改动后仍会静默过期（`stale design` 只提示，不自动重建）。
- 波次只由 requires 推导，不能钉死；跨波同文件/目录前缀冲突只做同波检测。
