# 0.4.37 — 证据里补上「在哪跑、用什么跑」

## 问题

`ac-evidence.json` 的每条记录只有 `command`、`exitCode`、`durationMs`、`tail`。同一个工作区里，同一条命令在不同的 `implRoot` 下完全可能一绿一红；而 `runner`（命令首词）是白名单判定的依据，却没落在证据里。事后核对「这条证据到底是怎么跑出来的」只能靠猜。

## 改了什么

`EvidenceItem` 增加两个**可选**字段（旧文件缺这两个字段仍能读，没有 schema 版本变更）：

- `runner`：命令首词（`pnpm` / `node` / `python` …），与白名单判定用的是同一个值
- `cwd`：执行目录（绝对路径）

`tasks/EVIDENCE.md` 的失败明细同步：每条失败现在打印 `命令：…` 与 `执行：runner=node，cwd=…，exit=3`。

## 测试

`tests/record.test.mjs` 增加一例：跑完两条 AC 后，断言 `items[0].runner === 'node'`、`items[0].cwd === outDir`，且 `EVIDENCE.md` 里出现 `runner=node` 与 `cwd=`。

## 实测

```

```

## 已知缺口

- `spawnSync(command, { shell: true })` 只拿到命令字符串，拿不到 shell 真正展开后的 argv。要记录「shell 真正执行了什么」得改成不带 shell 的 `spawn` + 自己解析引号，但那会让 `a | b`、`> out.log` 这类写法失效——权衡后本次只记录 `cwd` 与 `runner`。
- `tasks/EVIDENCE.md` 只在 `tasks/` 目录已存在时写（没跑过 `impl_gate_init` 就只落 JSON）。这是有意的，但文档没写，本轮一并补在 0.4.37 的说明里。
