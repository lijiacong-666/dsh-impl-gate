# dsh-impl-gate 0.3.0

这一版只修「会让设计产物互相破坏」的三处硬伤，不新增建模能力。

## 改动

### 1. `plan` 模式不再悄悄清空已填的 plan

- 目录里已有 `compose-plan.json` 时，`mode:"plan"` 返回 `E_PLAN_EXISTS`，并在 `detail` 里提示两条出路。
- 新增 `mode:"draft"`：读现有 plan，只重写 `SPEC-DRAFT.md`，**从不写 plan**。边填边看草稿用它。
- 确实要从头再来时传 `overwrite:true`，旧 plan 先改名成 `compose-plan.backup-<YYYYMMDDTHHMMSS>.json` 再重置，返回里带 `backupPath`。
- `outDir` 的「非空」判定改为白名单：只容忍 `compose-plan.json` 与 `SPEC-DRAFT.md`。

### 2. `impl_gate_init` 的失败结构与 compose 对齐

```json
{ "ok": false, "error": { "code": "EXPORT_REFUSED", "message": "…" } }
```

不再返回顶层 `code` / `message`——旧结构会撞上工具输出 schema 的 `additionalProperties: false`，在宿主里直接报 `returned invalid output`。

### 3. 建表迁移文件有唯一归属

有 `owner` 的表，其 owner 模块的 `files` 里必须出现 `migrations/*.sql`：

```json
"files": ["user-service/migrations/001_members.sql", "user-service/member.ts"]
```

否则 `PLAN_INVALID`，`problems` 指向 `/data/<i>/owner`。此前这条只写在 playbook 里，代码没有任何校验，盲测中六张表各写了一份 DDL。

## 升级注意

- 旧 plan 若没给 owner 模块配 migration 路径，会从「能物化」变成 `PLAN_INVALID`；按报错补一行 `migrations/*.sql` 即可。
- playbook 第 2 步已改成 `mode:"draft"`；继续用 `plan` 刷新草稿会得到 `E_PLAN_EXISTS`。

### 4. 设计阶段就能跑验收表

`materialize` 会同时写出 `.impl-gate/checklist.md`（32 行骨架）与 `.impl-gate/mapping.md`（按 `requires` 生成 `N1…`），配合 `impl_gate_check` 用 `implRoot=<outDir>` 跑一次，实测 `PASS 10 / FAIL 0 / NOT-RUN 22`。

### 5. 契约洞补到不用猜

- `http[].auth`：`public` / `session` / `admin`，4.4 打印「鉴权」列。
- `res:"void"`：渲染成「204（无响应体）」。
- `errors[].by`：4.3 增「归属模块」列；模块不存在直接 `PLAN_INVALID`。
- 第 1 节目标渲染成 `G1…`，与 `acceptance[].covers` 对上；有目标没被覆盖时第 6 节打印「覆盖缺口」。

### 6. 运行记录落盘

`impl_gate_check` 每次把记录写到 `<graphRoot>/.impl-gate/runs/<runId>.json`（保留 24 小时），内存缓存仍是 10 分钟；插件热重载后 report / verify_contract 仍可按 runId 或「该根最近一次」读回。

## 仍是已知缺口

- 设计阶段仍只有 A1–A5、B1、B2、B5、B7、Q10 能判；其余要等实现证据。
- A3 只重放 ≤3 条 specgraph 命令。
- `covers` 目前是可选字段，缺失时只在 `SPEC.md` 第 6 节提示，不算 `PLAN_INVALID`。
