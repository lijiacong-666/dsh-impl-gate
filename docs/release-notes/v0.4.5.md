# 0.4.5

`impl_gate_report` 现在给出一个结论：**这份文档能不能交出去**。

## 变更

- `ReportPayload` 新增 `readiness: { ok, reasons[] }`。
  - 评审与证据都齐、且 `check` 的 `consistency` 无矛盾 → `ok: true`；
  - 否则列出原因：没有评审、没有实现证据、评审还有 blocked、两边针对的 plan/SPEC 不一致、证据里有 FAIL。
- 渲染新增末行：

  ```text
  readiness: ready to hand over — review passed, evidence recorded, no contradiction
  ```

  或

  ```text
  readiness: not ready — 2 reason(s)
  - review round 3 has 1 blocked module(s), 2 blocking point(s)
  - implementation evidence has 1 FAIL row(s)
  ```

- 原因按固定顺序去重，同一句不会重复出现。
- `tests/readiness.test.mjs` 4 例。

## 为什么放 `report` 而不是 `check`

`check` 回答「32 条断言现在各是什么状态」，`report` 回答「这次运行说明了什么」。交付判断属于后者，而且 `report` 本来就要读缓存，不额外花钱。

## 升级注意

`report` 的输出多了一个对象。严格校验返回键集的脚本需要放行 `readiness`。
