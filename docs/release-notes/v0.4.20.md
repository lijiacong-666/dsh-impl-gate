# 0.4.20 — 两条 AC 抢同一个测试选择器

## 改了什么

- 新增警告 `AC_TEST_SELECTOR_OVERLAP`（第 36 类）：同一个测试文件的两条 AC，`-t` 选择器一个是另一个的前缀时提醒：

  ```
  M8: web-origin selector "web-origin" also matches M8: web-origin-allow "web-origin-allow" (web/tests/web.test.js)
  ```

## 为什么

这是我自己踩过的坑：药箱补 `web-origin-allow` 后，原来的 `web-origin` 选择器会连带把新用例也跑一遍。当时两条都通过，所以没人察觉；如果一条失败，另一条会跟着红，证据表上变成「两条都失败」——排查方向直接跑偏。

`impl_gate_record` 是逐条跑 `-t` 命令的，这种重叠会让「证据」失真：一条命令的结果并不只属于那一条 AC。

## 实测

| plan | `AC_TEST_SELECTOR_OVERLAP` |
|---|---|
| pillbox | 1（`web-origin` / `web-origin-allow`，真问题，未修——属夹具自身的债） |
| run-log | 0 |
| fitness | 0 |
| mini | 0 |

## 升级注意

- 旧 plan 可能新出一条：把两条用例名改成互不为前缀（`origin-blocked` / `origin-allowed`）。
- 只比同一文件内的选择器；不同文件同名不算冲突。

## 已知缺口

- 只认 `-t "…"`、`--test-name-pattern "…"`、`--grep "…"` 三种写法；正则选择器不解析（会跳过）。
