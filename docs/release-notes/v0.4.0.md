# v0.4.0

这一版把 0.3.8–0.3.22 串成一条可用的闭环：**需求 → 详细设计文档 → 独立评审 → 任务卡 → 实现证据 → 验收回显**。

## 新增

- `impl_gate_review`：把每轮评审落盘到 `.impl-gate/review.json`（三态、blocking、`evidence: SPEC.md:<line>`、
  `plan sha256 / spec sha256`、轮间 blocking 变化），`check` 会回显最新一轮并在 plan 变更后提示 stale。
- `impl_gate_record`：按任务卡里的验收命令真实执行，写 `.impl-gate/ac-evidence.json` 与 `tasks/EVIDENCE.md`；
  同一 plan 下多次 record 会合并不同模块的证据（`ref` 字段把证据对回 `AC-M<模块>-<n>`）。
- 契约字段：`http[].status / resHeaders / query[] / reqExample / resExample`、`types[].owner`、
  `errors[].by`、`runtime`（端口/启动/健康检查/迁移/回滚）、`globals.nfr`、`ui[]`、`flows[]`、`modules[].wave`、
  `openQuestions[]`。
- 机检：警告从 15 类扩到 26 类，包括 `AC_SHELL_LATER`、`AC_STATUS_CONTRADICTION`、`AC_TEST_UNRUNNABLE`、
  `LIST_PAGINATION_UNDECLARED`、`QUERY_PARAM_UNMAPPED`、`PAGINATION_MODE_CONFLICT`、`CONSTRAINT_FIELD_UNKNOWN`、
  `TYPE_OWNER_NO_SOURCE`、`TYPE_OWNER_MISSING`、`TOOLING_UNOWNED`、`IN_MEMORY_VS_TABLE`、`BOUNDARY_UNUSED`、
  `WRITE_NO_VALIDATION_ERROR`、`ERROR_UNUSED`、`FILE_OWNERSHIP_OVERLAP`、`STATUS_DEFAULTED`、
  `LIST_ORDER_UNDEFINED`、`PATCH_NULLABLE_AMBIGUOUS`、`CONSTRAINT_HAS_PATH`、`OPEN_QUESTIONS_PENDING`、
  `COVERAGE_GAP`、`AUTH_UNSPECIFIED`、`HTTP_ROUTE_UNCOVERED`、`AC_AUTH_UNSTATED`、`AC_HTTP_OUTSIDE_SHELL`。
- 文档：`playbooks/compose.md`（含「warnings 怎么读」与 17 条常见坑）、`playbooks/review.md`（三态、过线、
  六类必查）、两份案例 `docs/CASE-STUDY-run-log.md`、`docs/CASE-STUDY-pillbox.md`、`playbooks/examples/login.md`。
- `impl_gate_compose mode:"draft"`：只刷 `SPEC-DRAFT.md`，不动已填的 plan；plan 模式默认拒绝覆盖，覆盖前自动备份。

## 实测

- `run-log`（7 模块、24 路由）：六轮评审从 9 条 blocking 收到 0；M1–M7 全实现，`record` 21/21 PASS。
- `pillbox`（9 模块、22 路由、1118 行 SPEC）：六轮评审 0 blocking；九个互不通气的实现者写出 6,480 行、
  48 条 AC 全 PASS；`check` 输出 `PASS 10 / NOT-RUN 22` + `implementation evidence: PASS 48` + `review: round 10 … blocked 0`。

## 升级注意

- `review.json` 现在按 plan/spec 哈希校验：改了 plan 不重跑评审，`check` 会报 stale。
- `record` 只执行首词在白名单内的命令（pnpm/npm/node/python/git/… 共 17 个），其余标 `RUNNER_NOT_ALLOWED`。
- `materialize` 只拒绝覆盖「即将写入但不是本工具登记」的路径，已有的实现代码不会再挡重跑。

## 已知缺口

- 语义留白仍无法机检：长度上限、`null` 与「字段缺失」的区别、聚合口径、时区算法——只能靠评审或开工会上问。
- 32 条 gate 断言里 22 条默认 NOT-RUN（17 条依赖真实实现的命令回放、3 条占位、2 条不适用）。
- 评审者之间差异仍然大：同一份文档换人可能从 3/7 掉到 1/7，所以过线用 `blocking = 0`，不用「可开工比例」。
