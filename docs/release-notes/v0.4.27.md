# 0.4.27 — 兼容性文档从模板改成实测记录

## 改了什么

`docs/compatibility.md` 之前还是脚手架文案：`Profile: headless`、`Node ^22.19`、`Verified DSH: Pending`、`./client` 注册说明、`Manual verification: TODO`。整体重写为实际状态：

- 版本表：`engines.dsh: "*"`、Node `>=22.14.0`（0.3.10 放宽）、Python ≥3.11 且能 `import specgraph`、无 client 模块
- 集成契约六条：tools 服务（`inject: ['tools']`）、DSH 的 JSON schema 子集（附 0.2.0 那次 `JsonSchemaError` 原文）、bundle patch 与重复 id、热重载只随 profile 协调、写入边界只在 `outDir`、进程 spawn 失败的错误码
- 手工验证六条，带日期：七个工具可见、`login-demo` 的 PASS 10 / NOT-RUN 22、磁盘回落、代码已存在时的重物化、pillbox 49 条证据、`desktop` profile 禁止 `--dump-config`

## 为什么

这份文档是外部使用者判断「能不能装」的第一入口。写着 `Profile: headless` 和 `Verified DSH: Pending`，等于告诉人家「没验证过」；而实际上七个工具、两种安装方式、热重载行为都已经反复跑过。文档欠账比功能欠账更容易劝退人。

## 实测

- 表格里每个值都能在仓库里找到出处：`package.json`（engines/peer/dsh.bundle）、`tests/tool-schema.test.mjs`（schema 子集）、`docs/install-specgraph.md`（Python 依赖）
- 手工验证条目全部来自 2026-11-08 至 11-11 的实际运行记录，没有一条是「预计」

## 已知缺口

- 只在 Windows 11 + 当前 DSH 构建上验证过；macOS/Linux 未测，文档里没有暗示支持
- `dsh --dump-config` 对 Electron 管理的 profile 不可用，所以「已装载」的旁证依赖插件页与工具列表，而不是配置打印
