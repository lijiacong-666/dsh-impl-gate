# 0.4.25 — 一条命令做完整套检查

## 改了什么

- 新增 `pnpm verify:full`：`typecheck → build → test → check:package → smoke:ci`，一次跑到冒烟为止。
- `docs/QUICKSTART.md` 新增「接手一份别人已经生成好的 SPEC」：先看 `readiness`、再看 `review`/`consistency`、最后看波次里有没有文件被两个模块写；没有 `review.json` 的目录按草稿对待。

## 为什么

`pnpm verify` 只到「单测 + 打包检查」，单测都是构造的 plan——真实 plan 的警告集合变化它看不见。冒烟加进来后，这两个盲区合成一次运行；`smoke:ci` 在没有夹具的机器上会安静跳过，不会挡住别人。

## 实测

```
$ pnpm verify:full
… 313 tests / 308 pass / 5 skipped
Package ok: 71 files, 174527 bytes.
mini      OK   warnings=7  cards=1  check=10 pass
fitness   OK   warnings=7  cards=8  check=10 pass
pillbox   OK   warnings=2  cards=9  check=10 pass
run-log   OK   warnings=6  cards=7  check=10 pass
smoke ok
```

## 注意

- 裸机（没有四份 plan、没有 Python）上仍应 `pnpm verify`；`verify:full` 只在开发机/CI 里用。
- 接手别人的产物时，`readiness` 只反映「评审与证据是否对得上」，不代表业务上没问题——它不知道你的库存到底是片还是盒。

## 已知缺口

- `verify:full` 不覆盖桌面宿主的热重载验证；插件装载层仍然要人肉 toggle 一次。
