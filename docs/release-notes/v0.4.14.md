# 0.4.14 — 评审提示词带上「沉默清单」

## 改了什么

- `impl_gate_compose` 返回的评审提示词（`review.prompt`）新增 12 条**沉默清单**：单位、缺省与边界、排序分页、状态码与错误体、时间、不存在/已删/已改、事务边界、幂等与并发、长度上限、批量、页面数据来源、工具链。
- `playbooks/review.md` 同步这一节，人工评审也照这份清单走。
- 提示词里明确区分「已被机检覆盖的」与「只能靠人读的」：前者指向具体 warning code，后者是 5/6/7/8 这类语义问题。

## 为什么

外部诊断做过一次实验：让 AI 只读 SPEC 实写一个模块，暴露 12 条「文档没写、只能自己拍板」的缺口；而此前五轮评审对这 12 条的命中率是 **0/12**——评审能发现自相矛盾，发现不了留白。原因不是评审不认真，是提示词只说了「重点查自相矛盾」，没说「逐条问这些具体问题」。

把沉默清单写进提示词，等于把「留白」变成「有具体形状的问题」，评审才有机会回答。

## 实测

药箱第 14 轮评审（9/9 ready、blocking 0）用的还是旧提示词；新提示词在 `impl_gate_compose` 下一次物化时生效。`tests/review-prompt.test.mjs` 增一条断言：12 条编号必须齐，且包含「单位 / 缺省值 / 排序 / 状态码 / UTC / 事务 / 幂等 / 长度上限 / 批量 / 空态 / 测试命令」等关键词。

## 升级注意

无行为变化，只影响提示词文本与 playbook。
