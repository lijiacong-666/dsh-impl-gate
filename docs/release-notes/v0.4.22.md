# 0.4.22 — 每条警告都能被指到一段测试

## 改了什么

- 补了四条此前**没有单测**的警告的复现用例：`COVERAGE_GAP`、`ERROR_OWNER_MISSING`、`AUTH_UNSPECIFIED`、`AC_AUTH_UNSTATED`。
- `docs/WARNINGS.md` 新增一节「每条警告的最小复现」：37 类警告逐条列出它能被哪个测试文件复现，可以直接搜警告码找到构造好的坏例子。

## 为什么

写文档说「某类警告会提醒你」很容易，读者真正想问的是「给我看一下它长什么样」。以前 37 类里有 4 类连我们自己都只在真实 plan 上见过一次，测试里没有——那意味着改坏了也不会被发现。

现在 37/37 都有测试兜底，`docs/WARNINGS.md` 的映射表也是从测试目录扫出来的，不是手写（漏一个就露出来）。

## 实测

```
node --test tests/*.test.mjs  →  313 tests / 308 pass / 5 skipped
```

## 升级注意

- 只有测试与文档变化，运行时行为未变；`materialize` 的警告集合仍是 37 类。

## 已知缺口

- 映射表是「有测试覆盖」，不等于「测试覆盖了所有分支」：同一类警告的不同触发路径可能只测了一条。
