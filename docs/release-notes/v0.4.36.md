# 0.4.36 — 一个不做声的失败：node 的选择器写在文件后面

## 怎么发现的

`impl_gate_record` 在 Windows 上执行 `test` 命令时用的是 `spawnSync(..., shell: true)`。我想确认带空格、带中文的 `-t "登录 成功"` 能不能原样传进去，于是写了一个探针：同一份测试文件，一条 AC 用文件在前的写法，一条用 flag 在前的写法。

结果：

```
node --test a.test.mjs --test-name-pattern="登录 成功"   → 两条用例都跑了（包括本该被过滤掉的失败用例）
node --test --test-name-pattern="登录 成功" a.test.mjs   → 只跑命中的那条
```

**根因**：node 只解析位置参数**之前**的自身 flag。`--test-name-pattern` 写在文件后面时，它被当成脚本参数，选择器完全失效——整份测试文件都会跑。

**后果**：一条 AC 写 `node --test src/a.test.mjs --test-name-pattern="登录 成功"`，证据里记录的是**整份文件的结果**。别的用例失败会把它记成 FAIL，别的用例通过也可能替它背书。这比报错更糟，因为它看起来是绿的。

## 改了什么

新增警告 **`AC_TEST_NODE_FLAG_LATE`**（第 38 类）：扫每条 AC 的 `test`，命中「`node` + `.mjs/.cjs/.js/.ts` 文件 + 后面还有 `--test-name-pattern`」就报，并说明应对办法。

- 不误报 vitest 风格（`npx vitest run file -t "…"`，vitest 接受文件后的选择器）
- 不误报 flag 在前的 node 写法

同时补：`docs/WARNINGS.md` 的目录行与最小复现行、两份 README 的计数、`tests/node-flag-late.test.mjs`（3 例：flag 在后报、flag 在前不报、vitest 不报）。

## 实测

```
# tests 340 / pass 335 / fail 0 / skipped 5
```

## 已知缺口

- 只覆盖 `node --test`。`bun test`、`deno test` 的参数顺序规则不同，没有各自的断言。
- 这条检查看的是命令文本，不是实际执行结果；如果命令用变量拼出文件路径（`node --test $FILE --test-name-pattern=…`），正则可能漏。
- 更根本的修法是补证据时把「实际执行的 argv」记下来（现在只记 tail 与 exitCode），这次没做。
