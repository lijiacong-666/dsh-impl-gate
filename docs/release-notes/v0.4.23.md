# 0.4.23 — 一条命令跑完四份真实 plan

## 改了什么

- 新增 `scripts/smoke.mjs`（`pnpm smoke`）：对仓库外保留的四份真实 plan 依次跑 **materialize → init → check**，与 `scripts/smoke-snapshots.json` 比对三件事——警告集合、任务卡数、`check` 的 PASS/FAIL 计数。
- 快照用 `node scripts/smoke.mjs --update` 刷新；不带参数运行则在漂移时退出码 1，并打印「实际 vs 期望」。

## 为什么

单测都是「构造一个 plan、断言一个警告」，改坏了某个警告的**触发范围**（比如把静态资源从白名单里去掉）时单测照样全绿，只有真实 plan 才会暴露——今天补 `UNIT_MISSING` 的误报就是这么发现的（fitness 16 条、run-log 17 条）。

## 快照本身也是一份体检报告

| plan | 警告数 | 卡数 | check |
|---|---|---|---|
| mini | 7 | 1 | 10 pass / 0 fail |
| fitness | 7 | 8 | 10 pass / 0 fail |
| pillbox | 2 | 9 | 10 pass / 0 fail |
| run-log | 6 | 7 | 10 pass / 0 fail |

四个 plan 的 `check` 都是 10 条设计侧断言全过、22 条实现侧 NOT-RUN——这是这个工具的常态，`readiness` 是否 ready 取决于评审与证据，不由它决定。

## 注意

- 快照里的 `warnings` 是**有序数组**：调整了警告生成顺序也会触发漂移（这是故意的，顺序变了说明收集路径变了）。
- 四份 plan 在包外（`../_e2e/*`、`../../run-log`），没打包进 npm；跑 smoke 需要本机有这些目录与 Python + specgraph，否则会 SKIP 或失败。

## 已知缺口

- 只比「有没有」和「几条」，不比警告文案：改了文案（例如把字段名换成别的）不会触发漂移。
