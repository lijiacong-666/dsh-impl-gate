# 0.3.12

## 新增警告

- **`AC_STATUS_CONTRADICTION`**：验收里写「返回 201」，同一路由在 `http[]` 里声明的是 200（或反过来）。只在「状态码紧跟在该路由后面 24 个字符内」时才配对，避免一条 AC 覆盖多条路由时把 201 误套到 GET 上。这类矛盾会让实现者在两处之间二选一，必须先改文档。
- **`OPEN_QUESTIONS_PENDING`**：`openQuestions` 还有未决项时给出条数与前 70 字。它们本来只渲染在 SPEC 附录 A，开工阶段没人翻；现在在 materialize 的返回值里就能看到。

## 实测信号

- fitness（8 模块）：`AC_STATUS_CONTRADICTION(3)`——三条 POST 的 AC 写 201，`http[]` 里没写 `status`、按 200 兜底；`OPEN_QUESTIONS_PENDING(4)`。
- run-log（7 模块）：矛盾 0 条（调整配对规则后不再把 GET 的 201 误报），未决 3 条。
- mini（1 模块）：两类都没有——小计划本来就没歧义。

## 已知缺口

- 状态码配对是启发式的：只认「返回 / 状态码 / status + 数字」且紧邻路由；写成「应当以 201 结束」这类句式不会命中。
- 21 类警告都不拦截生成；要不要拦由评审环或 `impl_gate_check` 决定。
