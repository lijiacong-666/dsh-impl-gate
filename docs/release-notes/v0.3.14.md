# 0.3.14

## 改进

- **`impl_gate_check` 回显评审状态**：check 现在读 `.impl-gate/review.json`，多打一行

  ```
  review: round 3 by reviewer-f4abacad (independent subagent, read SPEC.md only) — ready 6 / clarify 1 / blocked 0 (blocking 0)
  ```

  如果那一轮评审时的 `compose-plan.json` 与当前文件不同，再追一行 `this review was recorded against an older compose-plan.json; run impl_gate_review again`。

  在此之前，评审与 gate 是两条互不相看的流水线：`review.json` 里写着「8/8 ready」，但 plan 又改了三版，check 仍然只会说 PASS 10 / NOT-RUN 22，看不出这份评审是否还覆盖当前文档。

## 实测（run-log）

```
impl_gate_check run-mwao3wi6-9094a7e6: PASS 10 / FAIL 0 / NOT-RUN 22 (32)
implementation evidence: PASS 21 / FAIL 0 / SKIPPED 0 (21 AC) — recorded 2026-11-10T11:58:57.545Z
review: round 3 by reviewer-f4abacad (independent subagent, read SPEC.md only) — ready 6 / clarify 1 / blocked 0 (blocking 0)
this review was recorded against an older compose-plan.json; run impl_gate_review again
```

这一行是对的：round 3 之后我们改过 AC 的 `test` 命令（改成可执行的 `npx vitest run …`），plan 的 sha256 已经变了。

## 已知缺口

- 只回显最新一轮；轮次历史与轮间 diff 仍然要自己读 `review.json`。
- `review.json` 与 plan 的绑定只看 sha256，不看「改了哪几行」——改一个错别字也会判 stale（有意偏保守）。
