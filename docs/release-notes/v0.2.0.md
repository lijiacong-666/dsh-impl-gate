# v0.2.0

## 新工具

- `impl_gate_compose`：把 `compose-plan.json` 物化成契约图谱、九节 `SPEC.md`、`export/` 指令包；`mode:"plan"` 只写空槽模板与草稿。
- `impl_gate_init`：按同一套波次生成 `<outDir>/tasks/`（`TASKS.md`、`cards.json`、逐模块任务卡），供多 AI 并行分发。
- 评审环写入 `playbooks/review.md`：materialize 之后、init 之前逐模块判「可开工 / 需澄清 / 不可开工」。

## 机检增强（G8–G10）

- G8：`not null` 且无 `default` 的列，必须在 `rowWriters` 模块的写入签名里有同名字段（snake→camel 启发式）。
- G9：对象数组参数（`T[]` / `Array<T>`）展开一层后参与列覆盖校验，报错带具体列名与字段名。
- G10：`data[].rowWriters` 与运行时写入方进入 §4.1；即使与 `owner` 相同也显式打印。
- 约束整节渲染修复（G8.1）：§3.1 不再丢失 `constraints`。

## 偏离登记

本版新增 D-13 … D-16，详见 [`docs/deviations.md`](../deviations.md)：

- D-13：`SPEC.md` 放在 `<outDir>/SPEC.md`，不放进 graphRoot。
- D-14：`types` / `errors` / `http` / `openQuestions` 与 `data[].owner` 为 v1 增量字段，`schemaVersion` 仍为 1。
- D-15：G7 的结构自洽校验不判语义正确，语义仍需人工评审。
- D-16：必填列覆盖校验是启发式，不展开嵌套 input 类型。

## 兼容性

- 未改 `impl_gate_check` / `impl_gate_report` / `impl_gate_verify_contract` 的语义。
- 旧 `compose-plan.json` 不引用新字段时仍可 materialize；引用类型名时必须补 `types`。
