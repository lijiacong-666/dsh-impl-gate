# 0.3.11

## 修复

- **分模块跑验收不再互相覆盖证据**：`impl_gate_record` 支持 `modules` 只跑其中几个模块。过去这样做会把 `.impl-gate/ac-evidence.json` 整份重写，只留下这一次跑过的模块，其他模块此前已经 PASS 的记录就丢了（真实项目里表现为「M1/M2 过了，单独补跑 M3 之后 evidence 只剩 M3」）。现在同一份 plan（`planSha256` 相同）下会保留未参与本次运行的模块记录，按验收编号合并后再写盘；plan 改过则按新 plan 全量重来，不混用旧证据。

## 升级注意

- evidence 文件的 `items` 可能是多次运行合并的结果，`summary` 也随之是全量统计；如果只看某一次运行，请按 `modules` 过滤或在命令输出里看本次结果。
- 合并只在 `planSha256` 一致时发生——改了 plan 记得先 `materialize` 再 `record`，否则 evidence 会整体替换（这是有意的：旧证据对应的契约已经变了）。

## 已知缺口

- `review.json` 仍只按轮次追加，不与 plan 哈希绑定；跨 plan 的评审历史需要自己比对 `planSha256`。
- 32 条 gate 断言里仍有 22 条默认 NOT-RUN（实现类要求需要在真实代码上跑）。
