# 0.4.43 — 把「`root` 就是 `graphRoot`」写进参数说明

## 问题

0.4.42 只在报错里补了一句提示，但**参数说明本身仍然含糊**：

```
root: { type: 'string', description: '检查根（graphRoot）的绝对路径。必填。' }
```

「检查根」不是个词。第一次用的人会自然地把 `implRoot` 填进去，然后在 `report` 上撞 `E_NO_PRIOR_RUN`。靠撞一次报错来学习语义，是文档欠债。

## 改了什么

- `impl_gate_report` / `impl_gate_verify_contract` 的 `root` 参数描述改为：
  `规格图谱根目录（graphRoot），必须与 impl_gate_check 传入的 graphRoot 完全一致（不是 implRoot）。必填。`
- 两份 README 的工具表同步为「`root`（必填，与 `check` 的 `graphRoot` 相同）」。
- `tests/report-verify.test.mjs` 的跨根用例多一条断言：错误 detail 里必须出现 `pass the same graphRoot`（0.4.42 的那句话，防止以后被改掉）。

## 测试

350 tests / 345 pass / 5 skip / 0 fail；`tsc --noEmit` 干净。

## 升级注意

纯文案 + 一条测试断言，无行为变化。工具签名（参数名、必填性）完全不变。

## 已知缺口

`check` 的 `implRoot` 与 `graphRoot` 是两个概念、`report` 只认后者——这个不对称本身仍然存在。要彻底消除，得让 `report` 也收 `implRoot`（用于找 `review.json`/证据）并定义「两者都给但互相矛盾」的语义。那是一次真正的接口变更，留给 0.5。
