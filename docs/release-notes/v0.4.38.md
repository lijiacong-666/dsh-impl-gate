# 0.4.38 — 打错 implRoot 不再伪装成「还没实现」

## 问题

`impl_gate_check` 的 `implRoot` 是可选的；不给就退回 `graphRoot`。但如果**给了**一个不存在的路径（打错一个字、少一层目录），旧行为是：

```
implementation: undefined
error: null
```

读起来像「还没有任何实现证据」，而不是「你给的路径不对」。用户会去重跑 `impl_gate_record`，而真正的问题是目录名。

## 改了什么

在 `runCheck` 里，`implRoot` 解析完成之后加一条守卫：**显式给出的** `implRoot`（参数或配置）不存在 → 直接

```
E_ROOT_MISSING — implRoot does not exist: D:\...\does-not-exist
```

不显式给时仍退回 `graphRoot`，行为不变。

## 实测

```
ok      | implementation: { pass:3, … , coverage:{declared:3,recorded:3,missing:[]} } | error: null
missing | implementation: undefined | error: {"code":"E_ROOT_MISSING","message":"implRoot does not exist: …"}
```

## 测试

`tests/check-implroot.test.mjs` 两例：

1. 给一个不存在的 `implRoot` → `E_ROOT_MISSING` 且消息含 `implRoot does not exist`
2. 不给 `implRoot` → 仍退回 `graphRoot`，错误里不出现 `implRoot`

## 实测

```
# tests 343 / pass 338 / fail 0 / skipped 5
```

## 已知缺口

- 只校验「目录存在」，不校验「里面有没有实现」。空目录仍会显示 `implementation: undefined`——这是对的（确实没有证据），但和「跑过 record 但没记录到」看起来一样。
- 同理，`graphRoot` 指向一个空目录时会先报 specgraph 的错，而不是「这不是一个契约图」。
